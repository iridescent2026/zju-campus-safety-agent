# 智安校园 · 校园安全数字孪生

> 浙江大学校园 AI 创新应用大赛参赛作品 · 管理服务方向 · 校园安全

面向校园真实安全场景的 AI 协同核查智能体。以「工程训练中心 / 后勤保障中心 / 校园室外区」为数字孪生底座，连接设备观测、人员定位、危险区域、作业计划与工单闭环，让安全员用自然语言完成「查状态 → 判影响 → 核人员 → 派工单 → 复核关闭」全流程。

当前校园版说明：[作品介绍](docs/campus-release.md) · [运行与部署](docs/campus-deployment.md)。旧工厂版部署记录仅供历史溯源，不是本版公网入口。

## 一句话说明

> 校园里每一处设备异常、每一次人员进入危险区域，AI 先帮你把证据核清楚，再交给有权限的人确认处置。

## 解决的核心痛点

高校校园安全管理的现实困难，不在"没有系统"，而在**证据分散、责任边界模糊、AI 容易编造**：

1. **信息分散**：配电房、水泵房、实验室、施工现场的数据各在一处，安全员要打多个电话才能拼出完整情况。
2. **责任边界不清**：设备异常是否影响教学？人员进入危险区该谁处置？口头沟通难留痕。
3. **AI 不可信**：通用大模型容易编造读数、虚构设备状态，不能直接用于安全决策。
4. **处置不闭环**：发现问题后，派单、处理、复核常常靠微信和纸面记录。

## 产品能力

### 1. 校园数字孪生空间

- 校园示意全景、工程训练中心（A 区）、后勤保障中心（B 区）与整体剖面四个视图
- 30 台校园设施：10kV 高压配电柜、油浸式变压器、排水泵组、板式换热机组、实验室压力试验机、机器人教学实验台等
- 12 处危险区域：校园基建施工区、塔吊吊装作业区、高压配电隔离区、气瓶与焊接危险区、UPS 蓄电池维护区等
- 26 名编号人员：校园安全员、后勤电工、实验指导教师、实验室管理员、泵房值守员、基建施工人员等

### 2. AI 协同核查（核心）

自由输入先由 DeepSeek 分析语义：匹配模板时按后台依据回答；不匹配时调用 DeepSeek 自由回答。快捷按钮直接使用本地模板。

系统会：

- 识别你问的是哪台设备（支持"排水泵""高压柜""PLC"等口语叫法）
- 调用后台工具读取**当前观测及来源**，演示环境使用模拟数据，不凭记忆编造读数
- 告诉你数据来源、采集时间、是否过期
- 明确区分「已核验」与「待核验」，缺失或过期数据不会当成正常
- 非模板问题由 DeepSeek 回答，只发送当前问题，不附带后台观测或历史模板回复；不宣称具有实时校园数据或设备控制权限

### 3. 证据链与工单闭环

- 每次回答都在后台留下工具调用记录（trace），可追溯
- 生成核查草案 → 安全员确认 → 指派维修账号 → 处理提交凭证 → **另一复核账号**关闭或退回
- 处理人与复核人强制分离，版本冲突与作业冲突阻止不合规操作

### 4. 多岗位权限

安全员 / 维修员 / 复核员 / 只读员 / 采集员 / 管理员，六个岗位各自可做的事不同，写权限全部在服务端校验。

## AI 协同设计要点

| 设计 | 说明 |
|---|---|
| 工具先行 | 模型只负责理解和组织语言，设备事实一律来自后台工具 |
| 证据溯源 | 每个读数标注来源、采集时间与是否过期；展示核查依据与实际执行记录 |
| 拒绝编造 | 回答中出现后台未提供的工程限值时，自动回退本地核查结果 |
| 人工确认 | AI 可生成草案，但不能直接派单、关单或控制设备 |
| 纠偏追问 | 设备名称或编号冲突时先追问，不猜测默认设备 |
| 权限隔离 | 模型无法突破岗位权限，历史对话被视为不可信上下文 |

## 模型配置

本机 Windows 执行 `python scripts/configure_local_model.py`，按隐藏提示输入 DeepSeek 密钥，保存到当前 Windows 用户的加密配置。云服务器使用后台密钥变量 `DEEPSEEK_API_KEY`，不要上传本机密钥文件。

使用 `WORKFLOW_RESPONSE_POLICY=classified-template` 启用“模型识别后选模板”的策略；编号支持 b05、B-05、Ｂ－０５ 和空白/连字符差异。模板读数只取后台，状态和故障影响分别处理。模型异常时显示本地回退及执行记录。详细变量见[部署说明](docs/campus-deployment.md)。

## 本地运行

Windows PowerShell：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe run_demo.py
```

打开 http://127.0.0.1:8080/ ，默认占用 8000、8001、8002、8080 端口。
端口冲突时先设置 `$env:DEMO_PORT_OFFSET='10000'`，页面改为 18080。

演示账号：

| 账号 | 密码 | 岗位 |
|---|---|---|
| demo-safety | SafetyDemo!2026 | 安全员 |
| demo-maintenance | RepairDemo!2026 | 维修员 |
| demo-reviewer | ReviewDemo!2026 | 复核员 |
| demo-observer | ObserveDemo!2026 | 只读员 |

## 推荐体验路径

1. 用 `demo-safety` 登录，进入校园全景
2. 搜索 `B-05` 或输入"排水泵什么状态"，查看 AI 如何调用后台工具回答
3. 问"如果排水泵坏了会有什么影响"，查看候选关联与核验条件
4. 生成核查草案，选择维修账号确认
5. 切换 `demo-maintenance` 处理并提交凭证
6. 切换 `demo-reviewer` 复核关闭
7. 进入 GIS 工作台，查看区域告警与人员进入记录

## 边界与声明

- 本项目为**原型演示**，设备读数、人员位置、危险范围为设计模拟，不是真实校园数据
- 坐标为设计示意，未做现场测绘配准
- 系统不控制设备、不授予停机或隔离许可，不能替代现场安全规程与人工判断
- 演示账号仅用于评审体验，不可用于公开部署
